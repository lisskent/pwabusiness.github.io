# Мой заработок

**Текущая версия: v23**  
**Формат: мобильное PWA-приложение для iPhone**  
**Назначение: учёт заработка, рабочих смен, расходов и личного денежного потока**

---

## 1. Что это за приложение

«Мой заработок» начинался как небольшой личный трекер смен для бариста: нужно было быстро записать выручку, количество рабочих часов и понять, сколько денег заработано за день.

Со временем приложение превратилось в полноценный **local-first финансовый PWA**. Сейчас оно объединяет четыре связанные задачи:

1. **Заработок**: учёт смен, усилений, часов, наличных и безнала.
2. **Планирование**: календарь рабочих дней, усилений и выходных.
3. **Деньги**: дополнительные доходы, расходы, категории, бюджеты и денежный остаток.
4. **Аналитика**: статистика заработка, расходы по категориям, финансовые показатели и прогноз.

Главная идея продукта:

> **Сколько я заработал → сколько потратил → сколько осталось → сколько времени моей работы это стоило.**

Приложение рассчитано прежде всего на людей с почасовой оплатой, процентом от выручки, несколькими местами работы или нестандартной системой расчёта зарплаты.

Доступны:

# 3. Места работы и формулы

Приложение поддерживает **несколько мест работы одновременно**.

Для каждого места работы задаются:

- название;
- цвет;
- тип формулы;
- ставка;
- процент;
- фиксированная сумма.

Поддерживаются четыре базовых типа расчёта:

### Почасовая + процент

```text
заработок = часы × ставка + выручка × процент / 100
```

Например:

```text
8 ч × 500 ₽ + (4 000 ₽ + 2 000 ₽) × 3%
```

### Почасовая

```text
заработок = часы × ставка
```

### Процент

```text
заработок = выручка × процент / 100
```

### Фиксированная сумма

```text
заработок = фиксированная сумма
```

Также сохраняется отдельный тип записи **«Усиление»**, для которого заработок рассчитывается по часовой ставке соответствующего рабочего места.

---

# 4. Снимок формулы в истории

Каждая сохранённая запись дня содержит `formulaSnapshot`.

Это важная часть архитектуры приложения.

Если сегодня ставка составляет 500 ₽/ч, а через месяц она изменится на 600 ₽/ч, старые смены **не пересчитаются задним числом**.

История сохраняет ту формулу, по которой заработок был рассчитан в момент внесения данных.

# 5. Месяц

Раздел «Месяц» показывает сводку за выбранный месяц.

Отображаются:

- общий заработок;
- заработок с усилений;
- количество рабочих часов;
- количество рабочих дней;
- средний заработок за рабочий день;

Месяцы можно переключать назад и вперёд.

# 6. Цели

Для каждого месяца можно установить финансовую цель.

Приложение показывает:

- целевую сумму;
- фактически заработанную сумму;
- процент выполнения;
- визуальный прогресс.

Цель хранится отдельно для каждого месяца.

---

# 7. Календарь

Календарь используется одновременно как история и как планировщик.

Можно отметить:

- рабочий день;
- усиление;
- выходной.

Для рабочих дней используется цвет соответствующего места работы.

Поддерживаются несколько мест работы в одном календарном дне.

Поведение режима выделения:

- повторное нажатие активного режима отключает режим;
- повторное нажатие на уже отмеченный день снимает отметку;
- режим «Выходной» работает отдельно;
- без активного режима нажатие на дату открывает данные дня.

Также календарь показывает заработок дня и наличие заметки.

---

# 8. Редактирование прошлых дней

Любой сохранённый день можно открыть и изменить.

Можно редактировать:

- место работы;
- тип записи;
- наличные;
- безнал;
- часы;
- усиление;
- итоговую формулу через выбранное место работы.

Можно добавлять несколько рабочих записей в один день.

Запись можно удалить.

---

# 9. Заметки и напоминания

Для каждой даты можно сохранить:

- текстовую заметку;
- время напоминания.

Заметка отображается в календаре и доступна из карточки выбранного дня.

### Ограничение PWA

PWA на iOS не может гарантировать выполнение произвольного JavaScript в фоне после полной выгрузки приложения системой.

Поэтому текущая версия не является полноценным серверным push-сервисом. Для гарантированных фоновых push-уведомлений потребуется backend и Push API / нативный слой.

# 13. Рабочее время как стоимость расходов

Одна из ключевых идей финансового раздела: показывать расходы не только в рублях, но и во времени.

Приложение рассчитывает среднюю стоимость рабочего часа на основе заработка и часов.

Например:

```text
Расход: 850 ₽
Средняя стоимость часа: 500 ₽

850 / 500 = 1,7 часа
≈ 1 ч 42 мин работы
```

То же отображается при создании расхода.

Это связывает два ранее независимых раздела приложения: заработок и расходы.

# 16. Умный прогноз заработка

В текущей версии прогноз больше не является простым умножением среднего заработка на количество оставшихся дней.

Для текущего месяца алгоритм использует несколько источников данных.

## 16.1. Запланированные смены

Если будущие рабочие дни отмечены в календаре, прогноз строится непосредственно по ним.

Для каждой будущей смены определяется:

- место работы;
- день недели;
- исторический заработок по этому месту работы.

## 16.2. Последние 56 дней

Для оценки будущей смены используется история последних 56 дней.

Более свежие данные имеют больший вес.

## 16.3. День недели

Если для будущей смены, например, приходится суббота, алгоритм смотрит на прошлые субботы.

Оценка строится примерно так:

```text
60%  среднее по тому же дню недели за последние 56 дней
25%  среднее по всем недавним сменам
15%  историческое среднее
```

Если одного из наборов данных недостаточно, используются доступные резервные значения.

## 16.4. Если календарь не заполнен

Если будущие смены не отмечены, приложение пытается восстановить рабочий ритм по истории последних 84 дней.

Оно анализирует, в какие дни недели пользователь обычно работал, и использует эти закономерности для оценки оставшейся части месяца.

## 16.5. Уровень уверенности

Прогноз сопровождается оценкой:

- **Высокая**: есть запланированные будущие смены;
- **Средняя**: прогноз строится преимущественно по историческим данным;
- **Низкая**: исторических данных мало.

Также отображается метод прогноза.

Пример:

```text
Факт 67 400 ₽ + 6 заплан. смен
Ожидаемо ещё 24 800 ₽

Прогноз: 92 200 ₽
Уверенность: Высокая
Метод: По графику
```

Прогноз является оценкой, а не гарантированным финансовым результатом.

# 17. Экспорт и резервные копии

Приложение поддерживает два разных типа экспорта.

## JSON

JSON используется как **полная резервная копия приложения**.

Он содержит внутреннюю структуру данных и подходит для последующего импорта обратно в приложение.

Импорт JSON заменяет текущие данные после подтверждения пользователя.

## CSV

CSV предназначен для таблиц и анализа данных.

Особенности:

- экспорт выбранного месяца;
- UTF-8 BOM;
- разделитель `;`;
- колонки на русском языке;
- совместимость с Excel и Google Sheets.

## Excel

Экспорт выбранного месяца создаёт Excel-совместимый файл `.xls`.

В таблицу попадают:

- дата;
- тип;
- категория;
- описание;
- наличные;
- безнал;
- часы;
- сумма;
- счёт;
- комментарий.

Это именно Excel-совместимый HTML-табличный файл с расширением `.xls`, а не полноценный бинарный `.xlsx`.

## PDF

PDF-отчёт создаётся через системную печать браузера.

Отчёт содержит:

- месяц;
- общий доход;
- расходы;
- остаток;
- прогноз;
- расходы по категориям;
- долю категорий;
- список операций и заработка.

На iPhone из системного окна печати можно выбрать сохранение в PDF.

## Экспорт выбранного месяца

В настройках можно выбрать конкретный месяц.

После этого CSV, Excel и PDF формируются именно для него.

# 18. Хранение данных

Приложение построено по принципу **local-first**.

Основное хранение:

```text
localStorage
```

Резервное хранилище:

```text
IndexedDB
```

При сохранении данные записываются в оба слоя.

Это позволяет приложению продолжать работать без постоянного подключения к серверу.

Сетевой backend в текущей версии отсутствует.

# 19. Структура данных

Основная структура приложения включает следующие сущности.

### Рабочие места

```js
works: [
  {
    id,
    name,
    color,
    formula: {
      type,
      rate,
      percent,
      fixed
    }
  }
]
```

### Рабочие дни

```js
days: {
  "YYYY-MM-DD": {
    entries: [
      {
        id,
        workId,
        type,
        cash,
        card,
        hours,
        earnings,
        formulaSnapshot
      }
    ]
  }
}
```

### Календарь

```js
calendar: {
  "YYYY-MM-DD": [workId]
}
```

или:

```js
calendar: {
  "YYYY-MM-DD": "off"
}
```

### Заметки

```js
notes: {
  "YYYY-MM-DD": {
    text,
    time
  }
}
```

### Цели

```js
goals: {
  "YYYY-MM": amount
}
```

### Категории финансовых операций

```js
expenseCategories: [
  { id, name, icon }
]

incomeCategories: [
  { id, name, icon }
]
```

Категории расходов и доходов намеренно разделены, чтобы разные типы операций не смешивались.

### Финансовые операции

```js
transactions: [
  {
    id,
    type: "expense" | "income",
    amount,
    categoryId,
    date,
    accountId,
    note,
    createdAt
  }
]
```

### Бюджеты

```js
budgets: {
  "YYYY-MM": {
    categoryId: amount
  }
}
```

# 20. Миграция данных

Новые версии не должны ломать старые данные.

В приложении предусмотрена цепочка миграции старых ключей localStorage и нормализация старых форматов данных.

Поддерживаются переходы со старых версий приложения, включая ранние структуры, где день хранился как один объект, а позднее стал массивом `entries`.

Также сохраняется совместимость с более ранними данными по местам работы и календарю.

# 23. Установка на iPhone

1. Разместить содержимое папки на HTTPS-хостинге.
2. Открыть адрес в Safari.
3. Нажать **«Поделиться»**.
4. Выбрать **«На экран Домой»**.
5. Запустить приложение с появившейся иконки.

Приложение работает как PWA и после первого запуска использует Service Worker для офлайн-кэша.

---

# 24. Что пока не является частью PWA

В текущей версии отсутствуют:

- аккаунты пользователей;
- серверная синхронизация;
- облачная база данных;
- мультиустройство;
- гарантированные фоновые push-уведомления;
- настоящий iOS Home Screen Widget;
- нативный Taptic Engine;
- полноценный `.xlsx`-движок;
- автоматическая синхронизация между несколькими телефонами.

Для настоящего массового продукта архитектура должна перейти к схеме:

```text
                 ┌──────────────┐
                 │   Backend    │
                 │  + Database  │
                 └──────┬───────┘
                        │
          ┌─────────────┼─────────────┐
          │             │             │
       PWA/Web       iPhone App     Widget
```

# 25. История разработки

Ниже собрана история проекта от самого первого PWA до текущей версии.

## v1 · Первый рабочий прототип

Изначальная задача была очень простой: сделать на iPhone приложение для ежедневного учёта заработка без Xcode и Mac.

Добавлены:

- наличные;
- безнал;
- рабочие часы;
- ставка;
- расчёт заработка;
- типы «Смена» и «Усиление»;
- месячная статистика;
- календарь;
- заметки;
- напоминание;
- локальное хранение;
- PWA-установка на iPhone.

Базовая формула исходного рабочего сценария:

```text
часы × ставка + (наличные + безнал) × 3%
```

---

## v2 · Расширение базового интерфейса

Проект перестал быть просто формой ввода и начал превращаться в полноценный трекер.

Основные направления изменений:

- более структурированный экран месяца;
- календарь как отдельная часть приложения;
- редактирование данных;
- улучшение отображения заработка;
- подготовка архитектуры для нескольких рабочих мест;

## v19 · Редактируемые категории и адаптивная полировка интерфейса

> Примечание: часть адаптивных правил v19 оказалась недостаточно жёсткой на отдельных размерах iPhone. Поэтому в v20 они были усилены, а перекрытие поля напоминания и переполнение выбора месяца исправлены отдельно.

v19 продолжила финансовую часть приложения и одновременно исправила несколько проблем с мобильной вёрсткой, которые особенно заметны на iPhone.

### Раздельные категории доходов и расходов

Категории теперь хранятся отдельно для двух типов операций:

- **категории расходов**: Еда, Транспорт, Дом, Развлечения, Покупки, Здоровье, Одежда, Подписки, Путешествия, Другое;
- **категории доходов**: Зарплата, Подработка, Премия, Подарок, Возврат, Другое.

В настройках появились два независимых редактора категорий. Для каждой категории можно:

- изменить название;
- изменить иконку;
- добавить новую категорию;
- удалить пользовательскую категорию.

При удалении категории существующие операции автоматически переводятся в «Другое». Для бюджетов расходов лимит удалённой категории также переносится в «Другое», чтобы история не терялась. Системные категории «Другое» удалить нельзя.

При создании операции список категорий автоматически зависит от выбранного типа: расход показывает только категории расходов, доход показывает только категории доходов.

### Совместимость со старыми данными

При обновлении с v17/v18 старый единый список категорий преобразуется в список расходов, а для доходов создаётся отдельный стандартный набор. Некорректные или устаревшие категории существующих операций безопасно переводятся в соответствующее «Другое».

### Адаптивная вёрстка

Исправлены элементы, которые могли вылезать за границы карточек или накладываться друг на друга на узких экранах:

- выбор места работы;
- поле выбора места работы и кнопка добавления;
- блок заметки и напоминания;
- кнопка сохранения напоминания;
- поля форм;
- строки настроек категорий;
- длинные названия категорий и мест работы.

Добавлены ограничения ширины, `minmax(0, 1fr)`, корректное `box-sizing`, перенос элементов на узких экранах и ellipsis для длинных названий. В результате элементы остаются внутри карточек и не заезжают друг на друга.

# 25.5. v20 · Исправление мобильного выравнивания

v20 не добавляет новый финансовый модуль, а доводит адаптивность v19 до состояния, в котором элементы действительно должны оставаться внутри своих контейнеров на iPhone. Предыдущие CSS-ограничения были недостаточно жёсткими: на некоторых размерах экрана строка напоминания продолжала перекрываться, а нативное поле выбора месяца для экспорта могло иметь ширину больше карточки.

### Напоминание

- строка «Напомнить» теперь строится в одну колонку на мобильных экранах;
- поле времени занимает всю доступную ширину карточки;
- кнопка «Сохранить» находится отдельной строкой и больше не накладывается на поле;
- для элементов применены `min-width: 0`, `max-width: 100%` и `box-sizing: border-box`;
- исправление не зависит от длины текста и системного размера шрифта.

### Выбор месяца для экспорта

- контейнер выбора месяца ограничен шириной родительской карточки;
- `input[type="month"]` принудительно ограничен `width: 100%`, `min-width: 0` и `max-width: 100%`;
- карточка экспорта и её дочерние элементы не могут расширять родительский контейнер;
- кнопки экспорта также получают ограничение ширины.

### Принцип v20

Это именно исправление вёрстки, а не косметическая маскировка. Цель версии — убрать горизонтальные переполнения и перекрытия на iPhone, включая случаи, когда Safari применяет собственные минимальные размеры к нативным полям формы.

# 27. v22 · Балансы, выплаты зарплаты и корректные регулярные операции

v22 продолжает v21 без удаления существующих функций и исправляет три важных сценария реального использования: фактический баланс денег, получение заработной платы и работу регулярных операций.

### Фактический баланс счетов

В редакторе счёта теперь можно изменить не только название и иконку, но и **текущий баланс**.

Например: `Карта → Текущий баланс: 4 000 ₽`.

После сохранения указанная сумма становится новой точкой отсчёта. Последующие расходы, доходы, переводы и выплаты зарплаты автоматически изменяют баланс. Для существующих счетов старый расчётный баланс сохраняется до тех пор, пока пользователь не задаст новую фактическую сумму.

Для этого у счёта появились поля `balance`, `balanceSetAt` и `balanceSetAtTs`. Ручная корректировка не смешивается с обычными расходами и доходами.

### Вывод зарплаты

Добавлена отдельная сущность выплат зарплаты. Теоретический заработок по сменам больше не смешивается с фактически полученной выплатой.

Можно создать:

- аванс;
- зарплату;
- фактическую сумму выплаты;
- дату получения;
- месяц, за который она выплачена;
- счёт, на который поступили деньги;
- комментарий.

По умолчанию учитывается график пользователя:

- **25 числа — аванс за текущий месяц**;
- **10 числа — зарплата за предыдущий месяц**.

Сумма выплаты вводится фактическая, потому что приложение не должно выдумывать размер аванса из воздуха. В карточке зарплаты отображаются **начислено / выплачено / ожидается**.

Выплата не увеличивает теоретический заработок второй раз. Она отражает получение уже заработанных денег и увеличивает фактический баланс выбранного счёта.

```js
salaryPayouts: [
  {
    id,
    type: "advance" | "salary",
    amount,
    date,
    periodMonth,
    accountId,
    note,
    createdAt
  }
]
```

Выплаты можно редактировать и удалять.

### Финансовый итог на главной

Исправлено обновление карточки «Финансовый итог».

Она теперь пересчитывается после сохранения смены, изменения цели, добавления или удаления финансовой операции и обновления приложения. Для текущего месяца учитывается фактически заработанное на текущую дату, расходы и дополнительные доходы.

### Регулярные операции

v21 создавал регулярную операцию сразу при открытии раздела «Деньги», даже если назначенный день ещё не наступил. В v22 это исправлено.

Теперь операция создаётся только после наступления указанной даты.

Например:

```text
5 сентября
Регулярная операция: 25 числа
→ операции ещё нет

25 сентября
→ операция создаётся датой 25 сентября
```

Если приложение не открывалось 25 сентября и пользователь открыл его 27 сентября, операция появится с датой **25 сентября**, а не 27 сентября.

После удаления созданная регулярная операция не появляется снова. Для этого регулярная запись хранит `generatedDates` с уже обработанными датами.

При добавлении новой регулярной операции она также не создаётся задним числом за уже прошедший день текущего месяца.

### Совместимость

v22 сохраняет миграцию данных v21 и более ранних версий. Старые счета получают корректные значения по умолчанию, а `salaryPayouts` и `generatedDates` создаются автоматически при загрузке.

# 28. v23 · Исправление редактирования счетов

v23 исправляет критическую ошибку в редакторе счетов. При нажатии «Сохранить счёт» во время редактирования существующего счёта приложение могло одновременно вызвать старый и новый обработчик кнопки. Старый обработчик сбрасывал `accountEditingId`, после чего новый обработчик воспринимал действие как создание нового счёта. Потому один клик превращался в маленький финансовый клонировочный завод.

Теперь:

- редактирование существующего счёта изменяет именно существующий объект по его `id`;
- новый счёт создаётся только когда редактор открыт через «Добавить счёт»;
- `accountId` у существующих транзакций не меняется;
- текущий баланс и точка отсчёта `balanceSetAt` сохраняются корректно;
- старый обработчик сохранения удаляется перед установкой нового, поэтому кнопка имеет только одну активную логику;
- миграция v22 сохраняется, поэтому существующие данные не требуют ручного переноса.

Другие функции v22 не изменялись.

# 31. Философия проекта

Приложение не должно превращаться в банковский интерфейс, бухгалтерию или очередной Excel с 74 вкладками.

Главный принцип остаётся простым:

> **Внести данные должно быть быстрее, чем открыть банковское приложение и начать думать, куда делись деньги.**

Поэтому все сложные расчёты выполняются автоматически, а пользователю показываются только те цифры, которые помогают принять решение.
